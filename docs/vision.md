# Grounds 愿景与核心原则

- 地位：**本项目的最高纲领。** 产品定位、核心价值和设计原则以本文为准；所有设计（决策记录、目标模型、实现方案、模块设计）都以本文为前提。
- 维护：修改本文须经项目负责人明确确认，并在相应决策记录中写明修改原因与影响。设计与本文冲突时，要么调整设计，要么先修订本文，不允许两者长期并存。
- 最近更新：2026-11-02，首版。依据见 [0001 决策记录](decisions/0001-unified-agent-evaluation.md) 的 D145。

## 1. 一句话定位

**Grounds 是开发者日常需求开发的本地工作台：先写清验收标准，再由任意 Agent 实现、由独立 Agent 核验；同时把每一次真实开发自动沉淀为可复现的私有评测资产。**

## 2. 要解决的问题

- 用 Agent 开发时，人的时间大多花在盯着 Agent、反复确认“它到底做完了没有”。人被困在循环里，很难同时推进多项工作。
- Agent 自报的“完成”不可信。声明、核验、交付混在一起，事后无法追溯它做了什么、依据是什么。
- 团队想知道“换一个 Agent、Skill 或模型之后，在**我们自己的**代码和需求上是不是更好”，却没有贴近真实工作的评测数据。公开基准与自己的工作相去甚远，手工构造评测集又太贵。

## 3. 核心价值

按重要性排序。前两条是 Grounds 存在的理由，后两条是支撑它们的必要条件，单独拿出来并不构成卖点。

1. **契约先行的日常开发。** 在需求定义时写清目标、约束和逐条验收条件。Agent 负责实现，独立 Agent 逐条核验并给出证据，人只在两端出现：定义契约、裁决结果。由此可以放心地同时推进多项任务。
2. **开发即评测资产。** 日常开发留下的任务、冻结的交付、验收记录和人工裁决，天然构成私有评测资产。补充评分依据（例如从被采纳的交付派生的隐藏测试或参考答案）后，就成为可复现的评测集，可以用来比较不同的 Agent、Skill 和模型。能否复现取决于归档的交付仍可取得，Grounds 会持续检查并如实标注。
3. **本地、低摩擦。** 下载 CLI、完成基础配置即可在本机使用，不需要部署服务。团队共享（共享数据库等）是可选增强，不是前提。
4. **隔离与并发。** 多项任务可以并发推进。Agent 的控制方式有两种：本地模式（自带 Agent 在宿主上工作，任务之间以独立 worktree 协作式隔离，可以按需为命令加上容器运行环境），以及容器托管模式（Grounds 在容器里运行 Agent，运行资源的隔离可以核实）。这是必要能力，但不是差异点。

## 4. 目标用户

| 用户 | 主要获得的价值 |
| --- | --- |
| 用 Agent 做日常需求开发的个人开发者与小团队 | 价值 1、3、4：并行推进、少盯 Agent、可信的完成判定 |
| 选型、调优 Agent / Skill / 提示词的人（团队负责人、AI 平台团队、Skill 作者） | 价值 2：基于自己真实工作的评测与对比 |

两类用户可能不是同一个人。价值 2 必须做到对第一类用户零额外成本，否则数据不会被积累下来。

## 5. 设计原则

1. **自带 Agent 优先。** 日常开发不要求用户更换 Agent：用户用自己习惯的 Agent（Claude Code、Codex 等）开发，Grounds 负责契约、冻结、独立验收和沉淀。Grounds 托管执行的 Agent 主要用于评测时“换一个 Agent 重跑”，不是日常开发的前提。
2. **证据优先。** 声明、核验、交付是三件不同的事；交付提交后冻结；结论可以追溯到确切的版本与证据；失败、未知、成功严格区分，不能为了简化而把未知或失败记成成功。
3. **独立验收是核心能力。** 验收者与实现者相互独立，逐条给出结论和依据；它的可信度决定整个产品是否成立，任何设计都不能削弱这种独立性。
4. **评测资产是副产品。** 不要求开发者为评测额外做事；“补充评分依据”是一等能力；对评测结论的统计意义如实说明，不夸大。
5. **自建差异化，集成基础设施。** 只自建 Grounds 独有的部分：契约任务、证据台账、冻结交付、独立验收、工作线、评测资产与评分。沙箱、隔离、容器编排、批量运行等基础设施，优先集成成熟的开源实现，不自己重造。
6. **本地优先、低摩擦。** 默认配置应当开箱可用；任何新增的必需配置、外部依赖或部署步骤，都要证明它换来了用户能感知的价值。
7. **简单优先。** 不为假想需求预建框架；复杂度只能用来换取用户能感知的价值或必需的可靠性（见 [软件设计原则](software-design.md)）。
8. **宣称须有证据。** 没有真实使用数据之前，不宣称提升了多少效率或质量；对外描述的能力必须已经实现并经过验证。

## 6. 非目标

- 不做通用 coding agent，不与 Claude Code、Codex 等 Agent 竞争。
- 不自建通用沙箱、容器编排或云端大规模评测平台。
- 不做 LLM 应用的线上观测与链路追踪平台。
- 不以公开基准排名为目标。
