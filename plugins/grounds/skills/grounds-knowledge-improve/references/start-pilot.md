# 开始一次有界的知识分析

1. 确认 doc/code 仓库、业务范围、允许修改路径、题数和总时间预算。没有自动评测能力时先告知用户，不承诺基线—修复—复测。
2. 在私有目录固定输入工作单；可按[材料助手](materials-helper.md)使用 `inputs` 和 `budget`。该工具只处理本地文件，预算恢复不重新计时。
3. 提出少量自足的问题，将拟定答案与来源证据分开保存。交给有授权的新核题上下文重新验证。
4. 依据确切来源定位文档缺口，提出或实施授权范围内的修复；保留用户改动。
5. 报告核验事实、文档 diff、尚未测量的效果和待执行回归。旧运行证据可引用，但不能冒充本轮执行。

详见[工作流](workflows/improve.md)和[材料边界](repository-materials.md)。不要用主 agent 自答、自评分填补已退役 runner 的能力缺口。
