# 有限的开发—验收—修复闭环

只有用户已授权自动独立验收和缺陷修复时才启动；明确最大轮次、允许修改范围及停止条件。没有轮次约定时先确认，不无限运行，也不默认为自动合并。

1. 按[开发与归档](develop.md)固定交付。
2. 按[独立验收](verify.md)创建全新子 agent，盲验并提交 gate。
3. 主 agent 读回 run 的 acceptance：accepted 则报告并停止修复；unknown/pending/基础设施失败先处理执行问题，不改成业务不合格。
4. rejected 时核对证据。契约歧义或范围变更交给用户裁决；已授权的代码缺陷用 `work continue --expected-head` 创建新运行、新目录，从冻结交付修复。
5. 每轮再创建新的评价者上下文，不继承旧验收判断或 worker 对话。达到预算上限、权限不足、归档失败或无法保持独立性时停止并报告。

CLI 是事实记录，主 agent 是协调者；没有 Python runner、可自动恢复的协调 journal 或后台模型调度器。结果不确定先读回原运行，不重置预算、不偷偷重跑到通过。闭环不授予 `work select/close`、合并、部署或目录清理权限。
